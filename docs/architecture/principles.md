# 디자인 원칙과 기준

> Figma 와이어프레임 "00 개요"에서 옮겼다. 이 문서가 원본이다.

## 판단 기준

화면에 넣거나 바꾸는 것은 **사용자가 무엇을 잃거나 얻는지**로 정한다. 보기 좋다는 이유만으로는 넣지 않는다. PRD의 화면 정책을 바꿀 때는 이유를 적어 PRD 레포에 PR을 올린다([DEC-0009](https://github.com/Fit-link-v2/Fit-link-PRD/blob/main/decisions/0009-ui-policy-from-user-need.md)).

## 원칙

1. 묻기 전에 답한다. "6/8"이 아니라 "2자리 남음"
2. 숨기지 말고 사유를 쓴다. 안 되는 버튼은 비활성 + 사유
3. 누르기 전에 결과를 보여준다. 차감 · 복구, 예약 후 잔여
4. 서버가 확정한 것만 보여준다. 낙관적 UI 없음
5. 회원 화면은 탭 없는 한 페이지
6. 시간표는 같고 개인 상태만 다르다
7. 강사가 쓸 글은 없다. 문구는 복사만
8. 다른 회원 정보는 노출하지 않는다
9. 의도 없는 UI는 넣지 않는다. 확인 창은 되돌릴 수 없는 동작에만

## 기준

| 항목 | 값 |
|---|---|
| 대상 기기 | 모바일 우선. 회원은 카톡 인앱 브라우저 |
| 기준 화면 | 360×800 |
| 터치 영역 | 48px 이상 |
| 간격 | 8pt 그리드 |
| 모드 | 라이트만 |
| 폰트 | Pretendard |
| 강사 화면 구성 | 하단 탭 수업 · 회원, 설정은 헤더 |

색 · 타이포 · 컴포넌트는 디자인 시스템이 나오면 이 폴더에 추가한다.
