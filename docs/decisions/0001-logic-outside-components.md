# 판정 로직은 컴포넌트 밖에 두고, 컴포넌트는 결과만 그린다

## 맥락

검증을 둘로 나눴다. 로직은 테스트(TDD), UI는 Storybook에서 시안 대조. 판정이 JSX 안에 섞여 있으면 테스트하려고 화면을 그려야 하고, story를 띄우려고 API를 흉내 내야 한다.

## 결정

- 수업 줄 상태 판정, 에러 코드 분기, 문구 조립은 **순수 함수나 훅**으로 만든다. 테스트 대상은 이쪽이다
- 그리는 컴포넌트는 **props만 받는다.** 데이터를 가져오지 않는다. story 대상은 이쪽이다
- 데이터를 가져와 둘을 잇는 컴포넌트는 화면마다 하나만 둔다
- fixture는 한 곳에 두고 테스트와 story가 같이 쓴다

## 검토한 대안

| 대안 | 버린 이유 |
|---|---|
| 컴포넌트를 통째로 렌더해 테스트 | 판정 하나를 확인하려고 화면 전체와 API mock이 필요하다. 테스트가 느리고 깨지기 쉽다 |

## 대가

- 작은 화면에서도 파일이 셋으로 나뉜다 (판정 · 그리기 · 잇기)
